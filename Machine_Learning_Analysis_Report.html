1. Overview

This report presents a complete supervised machine learning workflow applied to the Pima Indians Diabetes Dataset, a publicly available dataset of diagnostic measurements for 768 female patients of Pima Indian heritage. The task is binary classification: predict whether a patient is at risk of diabetes (Outcome = 1) based on eight clinical features. Two models were built and compared — a Logistic Regression baseline and a Random Forest primary classifier — following reproducible data science practices as described by Adhikari (2022). The dataset was sourced from the Jason Brownlee Datasets GitHub mirror: github.com/jbrownlee/Datasets.

2. Dataset Description

The Pima Indians Diabetes Dataset was compiled by the National Institute of Diabetes and Digestive and Kidney Diseases (NIDDK) and made publicly available through the UCI Machine Learning Repository. It contains 768 rows and 9 columns, covering exclusively female patients of Pima Indian heritage aged 21 and above. Eight features are diagnostic measurements; the ninth is the binary target variable (Outcome: 1 = diabetes, 0 = no diabetes). The dataset contains no explicit missing value markers — instead, physiologically impossible zero values in five columns (Glucose, BloodPressure, SkinThickness, Insulin, BMI) serve as proxies for missing data, a well-documented data quality issue that required explicit handling during preprocessing.

3. Modeling Approach

3.1 Data Preparation and Preprocessing

Zero-encoded missing value imputation: Zeros in Glucose, BloodPressure, SkinThickness, Insulin, and BMI were replaced with NaN and then imputed using the column median. Median was preferred over mean because these features are right-skewed (particularly Insulin and SkinThickness), making the median a more robust central-tendency estimate. A total of 652 cells were affected (out of 3,840 in the five columns — 17.0%), with Insulin (374 zeros, 48.7%) and SkinThickness (227 zeros, 29.6%) being the most severely affected.

Train-test split: An 80/20 stratified split (614 training / 154 test rows) was applied with random_state=42. Stratification ensures the class ratio is preserved in both subsets, preventing accidental over- or under-representation of the positive class in the test set.

Feature scaling: StandardScaler was fitted on the training set only and applied to both training and test sets. This prevents data leakage — the test set is treated as genuinely unseen data throughout the workflow (Pedregosa et al., 2011). Scaling is required for Logistic Regression (which is sensitive to feature magnitude) and applied uniformly to both models to ensure a fair comparison.

3.2 Model Selection

Baseline — Logistic Regression (solver='lbfgs', max_iter=1000): A linear probabilistic classifier that models the log-odds of the positive class as a linear function of features. It is interpretable, computationally efficient, and represents the standard linear baseline for binary classification tasks.

Primary — Random Forest Classifier (n_estimators=200, random_state=42): An ensemble of 200 decision trees trained on bootstrap samples, with random feature subsets evaluated at each split (bagging + random subspacing). Random forests capture non-linear interactions between features and are robust to outliers. Breiman (2001) demonstrated that these properties make random forests consistently effective on tabular datasets, including biomedical classification tasks. They also produce built-in feature importance estimates, enabling post-hoc interpretability.

3.3 Evaluation Metrics Justification

Given the class imbalance (34.9% positive), accuracy alone is misleading: a trivial classifier predicting "no diabetes" for every patient would achieve 65.1% accuracy without any learning. The evaluation therefore prioritises:

  • Recall (sensitivity): proportion of actual diabetics correctly identified. In a clinical screening context, false negatives (missed diagnoses) carry the greatest clinical risk — patients who are not flagged will not receive follow-up care.
  • F1-score: harmonic mean of precision and recall — the standard summary metric for imbalanced binary classification, balancing false negatives against false positives.
  • ROC-AUC: measures discriminative ability across all classification thresholds, independent of the operating threshold. A value of 1.0 is perfect; 0.5 is equivalent to random guessing.
  • Accuracy and Precision: reported for completeness and cross-model comparison.

3.4 Model Assumptions

Logistic Regression assumes a linear relationship between features and the log-odds of the outcome, independence of observations, and no severe multicollinearity among features. Random Forest relaxes all three assumptions but assumes that the training distribution is representative of the deployment population — an assumption that may not hold in this dataset (see Section 6).

The Random Forest outperforms Logistic Regression across all five metrics. The most meaningful differences are in F1-score (+0.0545, a ~10% relative improvement) and precision (+0.0522), confirming that the ensemble model better captures the non-linear interactions between features — particularly between Glucose, BMI, and DiabetesPedigreeFunction — that a linear model cannot represent.

The ROC-AUC values for both models (0.813 and 0.817) are notably higher than their accuracy scores, which reflects the class imbalance: both models can discriminate between diabetic and non-diabetic patients more reliably than raw accuracy suggests, but they struggle to convert that discriminative ability into high recall at the default 0.5 threshold. Adjusting the classification threshold downward (e.g., to 0.35–0.40) would increase recall at the cost of precision — a worthwhile tradeoff in a screening context.

5. Interpretation for a Non-Technical Audience

Imagine you are a doctor who needs to decide which patients should be referred for more detailed diabetes testing, based on a short questionnaire and a blood test. This analysis built a computer program — a machine learning model — that looks at eight measurements (like blood sugar level, body weight, and age) and makes an educated prediction about whether a patient is likely to have diabetes.

Out of every 100 patients who actually have diabetes in our test group, the best model correctly flags approximately 56 of them for follow-up. This means it misses about 44 — a limitation that is important to acknowledge. On the other side, when the model does flag a patient, it is correct roughly 65% of the time, meaning about 35 in every 100 flagged patients would turn out not to have diabetes (false alarms). Overall, it correctly classifies about 74 out of every 100 patients.

The single most useful piece of information the model uses is blood sugar level (glucose) — which makes good medical sense. Body weight (BMI) and a score that reflects family history of diabetes are the next most important signals. These results suggest that a simple, fast screening process focusing on these three measurements could help identify patients most likely to benefit from more detailed testing, without requiring expensive or invasive procedures.

It is important to emphasise that this model is a screening aid, not a diagnosis. No machine learning model should replace clinical judgment, and any flagged patient should be evaluated by a qualified healthcare professional.

6. Limitations and Potential Bias

6.1 Dataset Limitations

Narrow population scope: The dataset covers exclusively female patients of Pima Indian heritage aged 21 and above. This population has an unusually high genetic predisposition to Type 2 diabetes — one of the highest documented rates in the world. A model trained on this population cannot be generalised to other ethnic groups, men, or younger patients without retraining and re-evaluation on representative data. Applying this model in a different clinical context would risk systematic misclassification.

Extensive zero-encoded missing data: 48.7% of insulin values and 29.6% of skin thickness values were missing (encoded as zero). Median imputation was applied, but this approach introduces bias: imputed values reduce the variance in the affected columns and may distort the learned feature relationships. Multiple imputation methods would propagate the uncertainty more honestly but were not implemented here in the interest of simplicity. The high missingness rate in Insulin — the fifth most important feature — likely suppresses the model's ability to exploit insulin's true predictive signal.

6.2 Potential Sources of Bias and Ethical Considerations

Algorithmic bias from imbalanced data: The 65/35 class split means that the model is implicitly optimised to perform better on the majority class (non-diabetic patients). The relatively low recall (55.6% for Random Forest) demonstrates this: the model misses nearly half of all diabetic patients at the default threshold. In a real deployment, the classification threshold would need to be calibrated to the acceptable false-negative rate for the intended clinical use case. Deploying the model with the default threshold in a high-stakes screening scenario could cause systematic under-referral of diabetic patients.

Responsible use considerations: Any predictive model used in a clinical context raises ethical concerns about transparency, accountability, and equitable outcomes. A clinician using such a tool should understand its limitations, have access to the model's confidence scores (not just the binary prediction), and recognise that the training population may not reflect their patient population. Misuse of a model like this — for example, as an automated gate for insurance coverage decisions — would raise serious fairness concerns, as the model's errors are not uniformly distributed across age, weight, or number of pregnancies.
